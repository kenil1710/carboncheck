# CarbonCheck attack round

One internal round against `contracts/CarbonCheck.py` and `contracts/OffsetGate.py` before the final deployment. Each finding has tests in `test/test_attacks.py` (classes `A1`..`A8`) or `test/test_carboncheck.py` where noted. All High and Medium findings were fixed before deploying. Low findings are fixed or accepted, and the README "Scope" section states the accepted ones.

Severity: **High** means an attacker can get MATCHED (or open the gate) for credits the sources do not support. **Medium** means an honest batch can get a wrong verdict, or a stale or superseded MATCHED can still open the gate. **Low** means the outcome can only be UNVERIFIABLE or a refusal, or the behaviour is by design and documented.

| # | Area | Attack | Severity | Status | Fix / reason | Tests |
|---|---|---|---|---|---|---|
| A1 | fake batch contracts | File a batch NFT from a lookalike contract, the TCO2, the factory, the zero address, or the official address with a null byte, Cyrillic `а` or a full-width digit | High | Fixed in design | The batch contract is compared to one frozen address after `strip().lower()`; anything else is `REFUSED: NOT_TOUCAN_BATCH_CONTRACT`. Every RPC call goes to the frozen batch contract, the frozen factory, or the TCO2 the factory names; the filer's argument is never used as a call target | `A1FakeBatchContract` (9), `TestDoor.test_wrong_contract_refused`, `_tco2_address_`, `_factory_` |
| A2 | fake TCO2 | A batch held by a contract that answers `getAttributes()` with the right project and vintage | High | Fixed in design | The TCO2 must be the factory's `pvIdtoERC20(pvId)`, and the batch must be held by exactly that address | `A1.test_tco2_not_from_factory_ignored`, `TestChain.test_held_by_other_tco2_not_fractionalized` |
| A3 | stale chain state | A batch that was Confirmed and later detokenized (status 4) is filed at an OLD block where it was still Confirmed. Before the fix, "latest" meant the newest filing, so this MATCHED masked a newer UNVERIFIABLE and opened OffsetGate | Medium | **Fixed** | `latest_verdict` now ranks filings by the Polygon block they read, so an older block can never mask a newer one. OffsetGate also refuses a MATCHED that read a block older than `max_age` (`STALE_BLOCK`) | `A4Stale.test_old_block_cannot_mask_newer`, `test_gate_refuses_old_block_filed_fresh`, `TestGate.test_old_block_filed_later_cannot_mask_newer`, `test_fresh_filing_of_old_block_is_stale` |
| A4 | false double claims | Comparing raw unit numbers across all projects flagged honest batches: Verra reuses unit numbers across projects (Confirmed batches 9 and 889; 18 such pairs among Confirmed batches in the real data) | Medium | **Fixed** | Ranges are compared only within one Verra project. With that scope the real data has zero overlaps between Confirmed batches | `TestDoubleClaim.test_other_project_same_numbers_is_matched`, `TestOverlapMath.test_real_apx_ver_collision_is_numeric_overlap`, FEASIBILITY.md (d) |
| A5 | wrong MISMATCH | Verra writes a vintage spanning two years as `"2008 - 2009"`. Comparing it to the start year alone made 58 honest real batches MISMATCH | Medium | **Fixed** | The expected text is built from the serial's two dates exactly as Verra writes it; other spellings (`2008-2009`, `2008`) are MISMATCH | `TestVerra.test_verra_two_year_vintage_format` and 4 more, FEASIBILITY.md (d) |
| A6 | type confusion | `token_id=1000.5` or `block=9.57e7` were truncated by `int()` and accepted as another batch / block | Low | **Fixed** | `as_int`: only Python ints (not bools) or strings of ASCII digits; floats, hex and signs are refused | `TestDoor.test_token_float_refused`, `test_block_float_refused`, `test_token_hex_string_refused` |
| A7 | serial tricks | Leading zeros to alias a MATCHED range, full-width or Arabic-Indic digits, the literal text `1` (seen on chain, batch 1350), Cyrillic `С` in `VCU`, Unicode hyphens, zero-width spaces, comma or semicolon lists, lower case, trailing space or newline | High | Fixed in design | `parse_serial` accepts only `[0-9A-Z-]`, canonical numbers without leading zeros, real dates and exactly one serial; anything else is `SERIAL_UNPARSABLE` (UNVERIFIABLE) | `TestMalformedSerials` (40), `A2SerialTricks` (9) |
| A8 | serial tricks | Edit the project id inside the serial to borrow another project's numbers | High | Fixed in design | The serial's project must equal the TCO2's (`SERIAL_PROJECT_MISMATCH`), and the Verra record must carry the same project | `A2.test_project_swapped_in_serial`, `TestSerialAgainstTco2` |
| A9 | Verra lookalikes | The registry answers with near-miss serials (a prefix or suffix more), as a `contains` search would | High | Fixed in design | Only records whose `serialNo` equals the serial exactly count; two exact records are `VERRA_AMBIGUOUS` | `A2.test_verra_record_for_near_serial_does_not_count`, `test_verra_contains_search_superset_ignored`, `TestVerra.test_two_records_ambiguous` |
| A10 | overlap evasion | Split an already MATCHED range into many small batches, change the issuance id, change the vintage, extend one unit past the end | High | Fixed in design | Interval overlap on `[first, last]` within the project catches any shared unit; issuance id and vintage do not scope it | `A3OverlapEvasion` (6), `TestDoubleClaim` (16) |
| A11 | overlap evasion | Touching ranges reported as overlapping (off-by-one) | Medium | Fixed in design | `first_a <= last_b and first_b <= last_a`; touching is not overlap | `TestOverlapMath` (12), `test_touching_after_is_matched`, `test_touching_before_is_matched` |
| A12 | overlap griefing | A DOUBLE_CLAIMED or MISMATCH filing enters the index and blocks the honest batch | Medium | Fixed in design | Only MATCHED ranges are indexed; the first MATCHED batch keeps the range | `test_double_claimed_range_not_indexed`, `test_mismatch_range_not_indexed`, `test_unverifiable_range_not_indexed`, `A3.test_first_filer_cannot_be_displaced` |
| A13 | quantity off-by-one | A serial spanning `end - start` units read as matching a batch of that size | Medium | Fixed in design | Unit count is `last - first + 1`, compared to the on-chain quantity and to Verra's | `test_quantity_end_minus_start_trap`, `test_quantity_inclusive_exact`, `test_quantity_one_more`, `test_quantity_one_less` |
| A14 | lying sources | One RPC lies about quantity, status, owner, TCO2, attributes or block hash; an RPC claims a finality it lacks | High | Fixed in design | Both RPCs' raw answers must be identical (`RPC_DISAGREE`); each RPC's own finalized block must cover the filed block | `A7LyingSources`, `TestChain.test_rpc_disagree_*` (5) |
| A15 | consensus | Leader forges MATCHED, DOUBLE_CLAIMED, a stored field (remark), or a VERRA_NOT_FOUND | High | Fixed in design | Validators recompute the whole result and require it to be identical; DOUBLE_CLAIMED is never accepted from a leader (it is decided from storage after consensus) | `TestConsensus` (10), `A7.test_leader_reports_matched_for_mismatch` |
| A16 | consensus | Leader reports a transport failure to force UNVERIFIABLE | Low | Accepted | Needed so every filing ends even when a source is down. It asserts nothing, indexes no range and opens no gate; the batch can be refiled at another block | `A7.test_leader_claims_transport_failure_is_harmless`, `TestConsensus.test_leader_transport_unverifiable_accepted` |
| A17 | live registry | Verra changes between leader and validator reads | Low | By design | Validators disagree and the round does not settle; nothing is stored and the filer can refile | `TestConsensus.test_verra_changes_between_leader_and_validator` |
| A18 | stale verdicts | Use an old MATCHED at the gate after Verra or the batch changed | Medium | Fixed in design | OffsetGate refuses verdicts older than `max_age` (`STALE_VERDICT`) and blocks older than `max_age` (`STALE_BLOCK`); the latest verdict decides, so a newer MISMATCH or UNVERIFIABLE recheck closes the gate | `A4Stale` (4), `TestGate.test_refuse_stale`, `test_latest_mismatch_masks_older_matched`, `test_unverifiable_recheck_blocks_gate` |
| A19 | gate bypass | Get a MATCHED from another (e.g. demo) CarbonCheck and present it to the canonical gate; claim the same batch twice; feed the gate malformed registry answers | High | Fixed in design | The registry address is frozen at deploy; one accepted claim per batch; `decide` refuses any answer without integer `filed_at` / `block_time` in range and the exact verdict `MATCHED` | `A5GateBypass` (5), `TestGate` (23) |
| A20 | demo leakage | Use `demo_claim_range` on the canonical deployment to make honest batches DOUBLE_CLAIMED | High | Fixed in design | `REFUSED: DEMO_ONLY` unless the contract was deployed in DEMO mode | `TestDoubleClaim.test_demo_range_refused_on_canonical`, `A5.test_demo_range_cannot_touch_canonical` |
| A21 | inputs / storage | Huge serials from chain, huge Verra strings, non-integer or `NaN` quantities, booleans as numbers, Unicode or bidi characters in the gate note | Low | Fixed in design | Stored strings are bounded (serial 128, remark 240, beneficiary 100); quantities must be whole JSON numbers; the note is printable ASCII, at most 140 | `A6Inputs` (5), `TestVerra.test_quantity_fractional`, `_string` |
| A22 | remark as evidence | A Verra remark naming another party or no remark at all changes the verdict | Low | By design | The remark is stored and shown, never compared | `TestVerra.test_remark_recorded_not_decisive`, `test_remark_missing_still_matched` |
| A23 | rate limit | Many sender addresses (Sybil) | Low | Accepted | Filing is free but each write pays network fees; duplicates of (batch, block) are refused whoever files them | `TestDoor.test_duplicate_from_other_sender_refused` |
| A24 | registry vs reality | The real batch 1213's units appear on Verra as many later retirements to unrelated beneficiaries | Low | By design | The rule is an exact serial; this batch ends `VERRA_NOT_FOUND` (UNVERIFIABLE), never MATCHED. Code does not reassemble ranges from other records | FEASIBILITY.md (d), canonical seeds |
| A25 | docs truth | Docs that disagree with the code (addresses, RPCs, status, reason codes) | Medium | Fixed in design | Tests read RULES.md, README and FEASIBILITY.md and require the frozen addresses, both RPC URLs, `RETIRED` and every reason code the contract can return; `tools/final_check.mjs` checks addresses across all docs | `A8DocsTruth` (6), FINAL_CHECK.md |

Fixed before deployment in this round: A3 (Medium), A4 (Medium), A5 (Medium), A6 (Low). No High finding was open at deployment.
